# Launch checklist: no unapproved spending

This is an engineering checklist, not a claim that the AI is already live.

## Phase 1: code (implemented)
- [x] Private source repository
- [x] Local persistent journal
- [x] Demo autonomous goal loop
- [x] Local chat and one-shot question interface
- [x] Candidate code-change staging
- [x] Portable backup/restore
- [x] Deny-by-default consent registry
- [x] Tests and offline container definition

## Phase 2: real language model (not connected)
- [ ] Identify a currently available zero-cost inference option with clear terms.
- [ ] Confirm that it requires no payment method and cannot incur charges.
- [ ] Create an account and approve its access manually, if required.
- [ ] Store the token only in a secret manager, never the repository.
- [ ] Enable the model deliberately and run one conversation.
- [ ] Confirm responses are generated by the model rather than demo mode.
- [ ] Enforce request and token quotas outside the agent's editable process.

## Phase 3: host (not deployed)
- [ ] Select an authorized host that supports the required runtime and storage.
- [ ] Confirm actual free limits and idle-suspension behavior.
- [ ] Provision owner-controlled secrets and broker permissions.
- [ ] Configure encrypted backups and verify a restore.
- [ ] Confirm a functioning pause/stop switch.
- [ ] Run a supervised trial and inspect logs.
- [ ] Enable limited unattended operation only after the trial passes.

## Phase 4: autonomous development (partial)
- [x] Produce code proposals as data, not executable privileged instructions.
- [ ] Separate promotion service with a different identity and credentials.
- [ ] Test candidate changes in a restricted sandbox.
- [ ] Require independent approval for permissions and deployment controls.
- [ ] Add rollback and version pinning.
- [ ] Implement safe unattended promotion for a narrow set of modules.

## No-spending promise
The code does not initiate purchases. That alone cannot prevent third-party
API charges or paid compute use. Do not add payment credentials. Check
provider billing settings and use independent account-side quotas. Free
service availability and limits may change.

## iPhone-only workflow
The source can be viewed and edited in GitHub's mobile website. Running
Python requires a permitted remote environment or a Python-capable app.
GitHub alone is not a persistent host. The user must explicitly connect
external hosting or model accounts when needed.
